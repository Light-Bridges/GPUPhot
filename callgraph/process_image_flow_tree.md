-----------------------
- The `call @<n>` indicate the approximate line in the source code where it was
  call detected; They do not represent order of execution of the graph, but rather
  the textual position in the file (and therefore serve to locate the
  call site).
- The tree reflects the textual order within each function from the
  static analysis; however at runtime the order can
  vary if there are conditionals, exceptions, early returns or
  loops.
- OOM/GPU fault handling is reactive and sparse (try/except in
  several sites). Notes `on_exception` appear in the tree indicating the
  Typical actions observed (release mempool, retries, fallback).
